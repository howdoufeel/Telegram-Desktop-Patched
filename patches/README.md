# Расшифровки голосовых в экспорте Telegram Desktop

Патч исходного кода: `telegram-desktop-voice-transcriptions.patch`.

В ветке `main` этого репозитория патч уже применён. Раздел «Применение» нужен только для переноса доработки в другую копию Telegram Desktop; повторно применять патч здесь не нужно.

Это не установщик и не бинарное обновление установленного Telegram. Чтобы новая опция появилась в приложении, изменённые исходники необходимо собрать. Готовая сборка в этот комплект не входит.

## Изменения

- В настройках экспорта появляется флажок «Добавлять расшифровки голосовых», по умолчанию выключенный. Выбор сохраняется в настройках аккаунта.
- При включении обычные голосовые сообщения из выбранного диапазона дат обрабатываются методом Telegram `messages.transcribeAudio` с использованием текущего аккаунта.
- Расшифровки включаются в JSON и HTML. Скачивание самих аудиофайлов регулируется прежним флажком «Голосовые сообщения» независимо от получения текстов.
- Тексты сообщений и подписи сохраняются без подмены распознанной речью.
- Поддержаны отдельный чат, общий экспорт и экспорт темы форума. Для сообщений прежней обычной группы используется её исходный peer и ID до экспортного сдвига при миграции в супергруппу.
- Окно прогресса показывает получение расшифровок и ожидание Telegram. После завершения отображается число сохранённых расшифровок и записей без полного текста.
- Отмена экспорта останавливает запрос и дальнейшие отложенные попытки.

Названия новых элементов заданы по-русски в стандартном файле строк. Это персональная доработка; для публикации в upstream потребуется согласовать английские исходные строки и переводы.

## Формат JSON

К голосовому добавляется поле:

```json
"voice_transcription": {
  "provider": "telegram",
  "status": "done",
  "text": "Распознанный текст",
  "error": "",
  "transcription_id": "1234567890123456789"
}
```

`transcription_id` — строка, чтобы избежать потери точности 64-битного числа в JavaScript.

Статусы:

| Статус | Значение |
|---|---|
| `done` | Telegram вернул непустой окончательный текст |
| `empty` | Telegram завершил обработку, но вернул пустой текст |
| `pending` | Обработка не завершилась за отведённое число запросов; частичный текст сохранён с `TRANSCRIPTION_TIMEOUT` |
| `failed` | Запрос завершился ошибкой; её код сохранён в `error` |

HTML выводит текст с экранированием специальных символов, а также статус и код ошибки. При выключенном флажке новые поля в сообщения не добавляются и запросы распознавания не выполняются.

## Применение

База разработки: официальный репозиторий `telegramdesktop/tdesktop`, commit `72b3b71c3d6e450e5ef94a3112dd750a0168aa0b` от 7 октября 2026 года. Применение и откат патча также проверены на `v7.2.9` (`fb2e33209517e1a34637d837bfadb3783f2fd59c`). На другой версии сначала выполните `git apply --check`.

В корне вашего checkout Telegram Desktop, подставив действительный путь к патчу:

```sh
git apply --check /absolute/path/telegram-desktop-voice-transcriptions.patch
git apply /absolute/path/telegram-desktop-voice-transcriptions.patch
```

Команды не устанавливают приложение. Дальше нужна обычная сборка Telegram Desktop. В уже подготовленном дереве сборки:

```sh
cmake --build out --config Debug --target Telegram
```

Для первоначальной подготовки используйте [официальную инструкцию macOS](https://github.com/telegramdesktop/tdesktop/blob/72b3b71c3d6e450e5ef94a3112dd750a0168aa0b/docs/building-mac.md). Нужны зависимости, Xcode и API-реквизиты приложения. Инструкция оценивает полный процесс примерно в 55 ГБ свободного места; создание одного патча такого объёма не требует.

Откат исходников, если изменённые строки после применения не редактировались:

```sh
git apply --reverse --check /absolute/path/telegram-desktop-voice-transcriptions.patch
git apply --reverse /absolute/path/telegram-desktop-voice-transcriptions.patch
```

## Проверки

Проверены применение и откат патча на обеих указанных версиях, отсутствие ошибок пробелов в diff и совпадение применённого патча с подготовленными исходниками. Изолированные тесты успешно выполнены, в том числе из дерева v7.2.9 после применения поставляемого патча.

После применения доступны изолированные тесты:

```sh
python3 Telegram/Tests/export_transcriptions/run.py
```

Нужны Python 3 и компилятор C++20 (`clang++` по умолчанию, переопределение через `CXX`). Тест извлекает реальные методы очереди из изменённого `export_api_wrap.cpp` и компилирует их с тестовыми адаптерами API, часов и модели данных. Запросы к Telegram не отправляются.

Проверяются политика повторов и 13 сценариев: выключенный флажок, фильтрация дат и типов медиа, миграция группы, тема форума, частичный и окончательный ответ, таймаут, ошибка одного голосового с продолжением экспорта, длительное ожидание сервера, повторяющийся FLOOD, пустой ответ, отмена во время ожидания, отмена во время запроса и остановка обработчиком прогресса.

Эти проверки не заменяют компиляцию целого клиента с настоящими типами Qt/MTProto. Полная сборка, отображение флажка в работающем Telegram и реальный экспорт с аккаунтом Premium здесь не проверены. Для приёмки после сборки нужно экспортировать небольшой чат с несколькими голосовыми, сравнить тексты с Telegram, проверить выключенный флажок, отмену и итоговые счётчики.

## Ограничения

- Патч обрабатывает обычные голосовые сообщения, а не видеокружки, произвольные аудиофайлы или вложенные аудио в rich messages.
- Telegram определяет доступность распознавания, ограничения длительности и квоты. Для массового экспорта предполагается Premium; отсутствие подписки не блокируется в интерфейсе, поскольку у Telegram бывают бесплатные квоты и исключения для групп.
- Для незавершённой расшифровки выполняется до 36 запросов с интервалом 5 секунд; при исчерпании попыток частичный текст не выдаётся за окончательный.
- Для `FLOOD_WAIT` и `FLOOD_PREMIUM_WAIT` выдерживается указанное сервером время. После пяти повторов подряд дальнейшие запросы распознавания в этом экспорте прекращаются, а оставшиеся голосовые получают явную ошибку. При `FLOOD` без времени задержка постепенно увеличивается.
- Между обработанными голосовыми выдерживается пауза 1 секунда. Большой архив может обрабатываться долго.
- Постоянного кеша и возобновления прерванного экспорта в этой версии нет. Повторный экспорт снова обращается к API; уже записанные файлы предыдущего экспорта не используются как кеш.
- Патч не меняет установленные приложения, не читает `tdata`, не авторизуется в аккаунте и не отправляет сообщения от пользователя. Получение расшифровок начнётся только в собранном клиенте после включения опции и запуска экспорта.

Лицензия изменяемых исходников определяется [лицензией Telegram Desktop](https://github.com/telegramdesktop/tdesktop/blob/v7.2.9/LICENSE).
